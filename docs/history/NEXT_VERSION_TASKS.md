# Next Version — Implementation Checklist

This checklist can be executed by another developer or an AI. It follows `MIGRATION_PLAN.md`. Each task has an ID, the files to change, and **Done when** acceptance criteria.

Status marks: `[x]` done, `[~]` partly done or waiting on an operator step, `[ ]` not started. Phase 1 status as of 2026-09-25; every phase brought up to date with what is live on 2026-10-01 (`docs/RELEASES.md` has each release).

**Live on mylistsaddon.com (2026-10-01):** Phases 0 to 6 and Phase 7 so far (Releases 1 to 12, the release branch `claude/elegant-ride-o7m8fh`). Switches on: `FF_V2_LISTS_READ`, `FF_SESSIONS` (with `TOKEN_ENCRYPTION_KEY` and `LOOKUP_PEPPER`), `FF_V2_LISTS_ONLY` and `FF_EVENT_TRACKING` (both one-way). Being turned on: `FF_PROVIDER_BREAKER`, `FF_CHART_SNAPSHOTS`, then `FF_SHOW_SCHEDULE` and `FF_NEW_UI`. Off: `FF_CANONICAL_IDS`, `FF_MATERIALIZER`, `FF_INSTALLS`, `FF_V2_LISTS_API`, `INSTALL_MIGRATION_PERCENT`, `FF_CSP_TT_REPORT`.

**Rules for every task:**

- **No npm, no `src/` tree, no frameworks (D-11).** Where a task names a `src/<area>/<file>.js` module, it means that responsibility: put it in the numbered file that owns the area (`NEXT_VERSION_ARCHITECTURE.md` §7.2 maps them), or in a new numbered server file after `26_`. Client code stays in `09_`–`24_`, as vanilla JavaScript.
- Keep `worker_entry_combined.js` a single pasteable ES-module file. Never hand-edit it; always regenerate it with the build.
- Schema changes are additive until Phase 10. Every migration is recorded in `schema_migrations`.
- Behavior changes go behind a `FF_*` Worker variable, default off, unless the task says "hotfix".
- The full test suite must pass. Add or adjust tests in the same change.
- Update `CHANGELOG.md` for user-visible changes.
- Line references are to the current numbered sources (2026-09-25).

- [x] **P7-1** CSP: `script-src 'self' 'nonce-{rand}'`; `style-src 'self' 'nonce-…'` (or hashes); self-hosted fonts and `fflate`; `require-trusted-types-for 'script'` in report-only mode, then enforced. *Done when:* no violations in E2E runs. — **Status:** Done 2026-09-29 (Arena); the E2E half waits on P9-3, and the report-only header is how violations are collected until then.   - **A fresh nonce per response, from the one place that cannot be skipped.** `cspNonce()` (02_) makes 128 bits of base64url from the platform CSPRNG; the boundary (`export default fetch`, 26_) makes one per request and passes it to `withSecurityHeaders`, which sets the policy and substitutes `CSP_NONCE_PLACEHOLDER` (`%%CSP_NONCE%%`) in the body.
